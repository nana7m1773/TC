# Windows 桌面界面接入

`0.3.0` 可对本人选定的聊天窗口完成：读取或截图 → 确认消息 → 生成本地回复 → 编辑审核 → 发送一次。先在“账号连接”打开官方应用，再进入“桌面界面接入”。不需要把窗口藏在后台；多个候选输入框可由本人明确选择。

## 从登录到回复

1. 在“账号连接”点平台的“打开官方网页登录”或“打开本机客户端”，本人完成登录并打开会话。哔哩哔哩、微博、WhatsApp、微信提供隔离官方网页窗口；QQ 个人号使用已安装的官方客户端。微信网页版提示账号不支持时使用本机微信。打开窗口仅表示启动请求或窗口已打开，登录状态和消息权限仍需实际核对。
2. 进入“桌面界面接入”，点“刷新可选窗口”，明确选择窗口。需要时点“显示所选窗口并核对”，确认应用、账号和当前会话。发布者信息供核对来源，不作为枚举窗口的唯一门槛；浏览器签名也不能证明其中网页或账号正确。
3. 点“授权读取所选窗口”；需要图片时另点“授权截取所选窗口”。读取后，在“本人选择输入框与发送方式”选择实际候选项。多个输入框可分别选择，不会因为窗口有多个 Edit 控件就一律拒绝。
4. 从文字预览圈选本次对方消息，点“将圈选文字作为本次收到内容”；也可本人填写。填写并核对“本人确认的当前会话名称”，排除导航、搜索框内容、本人消息和其他会话文字。
5. 勾选允许本地生成本次草稿，点“生成本地回复草稿”。在草稿框查看、修改内容；生成尚未写入原客户端。缺少模型时先点“准备本地模型”。
6. 确认所选输入框为空、发送方式正确，再点“核对草稿并发送一次”。应用重新检查窗口、消息快照、输入框和规则，尝试写入并触发一次发送。随后到原应用核对实际结果，在本页或“待审核回复”填写核实依据。

本流程处理本人确认的一条消息；尚无可靠的通用新消息区域／发送者适配器。保持目标会话不变，执行期间不要在目标输入框打字。若没有可用输入控件，可把内容放入手动消息输入生成草稿，再本人复制到原客户端。

## 选择输入框与发送方式

| 页面选项 | 行为与要求 |
| --- | --- |
| 直接写入 | 对本人选定且支持 ValuePattern 的可写输入框赋值，再用所选发送按钮或快捷键提交；写入后检查文本。 |
| Unicode 键盘输入 | 显示并聚焦本人选定的窗口及输入框，通过 Unicode 键盘事件输入；仅接受单行文本，不含换行或制表符。目标切换、焦点变化或输入文本不一致时停止。 |
| 发送按钮 | 调用本人选择方案中绑定的可用按钮。 |
| Enter／Ctrl+Enter | 本人先到目标应用确认其发送设置，再明确选择对应方案；不是控件失败后自动猜测的备用方式。 |

已有草稿、不可读或不可写的控件、窗口／消息变化会阻止提交。Unicode 输入不依赖把文字先放入剪贴板，但客户端、输入法和系统焦点仍可能影响行为；可用方案以当前实际检测为准。未找到合适方案时复制草稿手动发送。

## 截图、视觉和语音

截图只针对本人选择的窗口，可能包含聊天、草稿或登录内容。已明确检测到捕获保护时拒绝；系统无法查询保护状态时不一律拒绝，会返回状态供核对。截图失败、黑图或模糊内容需要本人处理。截图不建立可信的会话身份或消息快照。

安装匹配的本地视觉组件后，可点“用本地模型理解此窗口”，再核对文字和发送者。若无法取得原生窗口快照／输入目标，截图理解仍可用于手动草稿，不能单凭图像提交窗口发送。

“语音、回复语言与延迟”支持本人选择的本地音频文件，由本地 Whisper 转写；不自动读取客户端语音，也不录制声卡。核对转写和消息归属后用于本次回复。该页面的文字、截图和音频使用本地组件，不自动上传 API。

## 发送结果与暂停

发送后显示“发送结果未知”，只暂停并锁定对应会话；其他会话不因本次结果一律停止。检查原应用消息列表和输入框，再选择已发出或未发出并填写核实依据。离页或重启后，到“待审核回复”找到“结果待核实”的草稿处理。核实会解除该会话的待核实状态，**不会自动重发旧草稿**。

“停止并撤销授权”、切换窗口、修改消息／选项、暂停或接管会使旧授权失效。提交后的操作可能已部分完成，应用不清空或恢复现场草稿，也不自动重试；先核对原应用再开始新任务。

## 原生提交的检查

窗口选择绑定进程、PID、进程启动时间、HWND 和标题，有效期 5 分钟。准备阶段复验窗口、消息快照和本人选择的输入目标，返回 30 秒单次 ticket；准备不写入。提交先消耗 ticket，再验证相同绑定、空输入框、内容和规则，随后写入并触发所选发送动作。前台窗口可用；Unicode 方案会激活并聚焦目标。

UIA 检查与实际写入不是原子操作，目标程序或本人操作仍可能在两者之间改变内容。一次原生发送调用只说明已尝试提交，不能证明平台接受或联系人收到。

## 当前验证

`0.3.0` 已完成窗口脚本语法检查、.NET Framework 4.8／C# 5 兼容编译及 41 项窗口协议测试；前端和服务测试检查目标选择、生成与审核分离、授权失效及未知结果处理。协议测试使用替身，不代表已在五个真实 Windows 客户端完成发送。

`0.2.0` Linux 真实 9B 五平台模拟、公开合成截图和 Whisper 报告保留为历史资料；其中发送回执来自模拟通道。Windows 客户端版本、真实控件、输入法、DPI、截图与一次发送仍需在目标设备记录。本版具体日志见发布验证包；开发工作流见 [窗口操作技能](../skills/lbot-computer-use/SKILL.md)。Android 使用系统通知接入，详见 [使用指南](USER_GUIDE.md)。
