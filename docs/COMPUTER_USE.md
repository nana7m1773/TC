# Windows 按窗口操作

L-BOT 的 computer use 路线通过 Windows UI Automation（UIA）和所选窗口截图操作**本人已登录的官方客户端／网页**。当前流程只处理本人核对的一条消息：读取预览、确认会话与消息、授权本次回复、生成本地草稿、复核规则、准备并提交一次原生操作。

当前没有可靠的“新消息区域／发送者角色”适配器。整窗文字可能混有导航、控件名称、本人消息和对方消息，所以不能据此猜收件人，或宣称已实现后台持续收消息并代回。

## 支持范围与前提

此入口仅支持 Windows 10/11 桌面原生版。Android、浏览器和 Linux 不会伪造 Windows 控件或发送结果。五平台流程面向 QQ、微信、哔哩哔哩、微博、WhatsApp 官方客户端／官方网页；当前真实客户端版本的可访问控件支持情况仍需逐一验证。

可枚举目标包括限定进程及通过发布者签名检查的官方客户端，以及 Edge、Chrome、Firefox。浏览器发布者签名只证明浏览器身份，**不能证明当前网页就是官方平台或当前聊天账号正确**；本人必须检查网址、账号与会话。窗口标题也不是收件人身份认证。

应用不代替官方登录，不读取密码、登录 cookie 或令牌来伪装 API 授权。正式身份登录与消息权限是不同能力，官方来源与申请条件见 [登录与权限说明](LOGIN_AND_PERMISSIONS.md)。

## 只读预览、截图与语音

1. 本人在官方客户端／网页登录并打开目标会话，然后进入 L-BOT“按窗口操作”。
2. 点击“刷新可选窗口”，明确选择窗口。授权绑定所选进程、PID、进程启动时间、HWND 和标题；窗口选择有效期为 5 分钟。
3. 勾选允许本次读取后，点击“读取所选窗口文字”。只读结果来自所选窗口提供的可见 UIA 辅助功能文本，需本人核对归属；预览不会自动当作对方新消息。
4. 如需截图，单独勾选整窗截图授权，再点击“截取所选窗口”。`PrintWindow` 仅接收该 HWND，图像只进入本次内存，可能包含私人消息、草稿或登录界面。受捕获保护、不支持或尺寸检查失败时停止；黑图或看不清的内容由本人处理，不作为可信消息输入。截图不是经过确认的消息结构。
5. 安装匹配的本地视觉组件后，可理解该截图。模型的文字识别、人物／账号判断可能出错，需本人复核；图片中的指令不能改变权限。
6. 语音只来自本人选择的本地文件，并由本地 Whisper 转写。当前页面不自动读取社交聊天语音，也不录制客户端声卡。核对内容和发送者归属后才能用于本次任务。

本页面截图、文字和音频交给本地组件，不默认调用 API 或上传。也可点击“放入手动消息输入，暂不发送”，转入本人审核草稿的流程。

## 已确认消息的一次自动回复

1. 在只读预览中选中本次对方消息，使用“将圈选文字作为本次收到内容”，或由本人填写并核对内容。排除本人消息、导航和其他会话文字。
2. 回到官方客户端核对当前会话名称，再在 L-BOT 填写。允许的会话名称每行一个，须与本人确认名称完全匹配；同名联系人仍需本人核对账号和实际窗口。
3. 勾选本人已核对会话与消息，启用本窗口本次回复规则，设置回复语言、等待时间与敏感内容处理。暂停状态不允许执行。
4. 查看原生能力说明。只有能唯一定位到**空且可写的 ValuePattern 输入框**和**唯一可调用的 InvokePattern 发送按钮**时，才能准备提交。已有草稿、控件缺失、存在歧义或窗口变化会阻止操作。
5. 明确勾选授权“仅此一次”的本地生成、写入和触发发送，然后执行。草稿生成和等待期间仅轮询核验已选窗口，不检测未知新消息。
6. 提交调用后，状态为**发送结果未知**，应用暂停并锁定该窗口本页的自动发送。本人到官方客户端检查输入框与消息列表；应用不会宣称发送或送达成功，也不会自动重试。

授权会在切换窗口、修改消息／规则、暂停、接管、标题变化、快照变化或过期时撤销。托盘暂停与页面“停止并撤销授权”能阻止后续步骤；已调用原生发送的任务仍需本人核对。

## 原生准备与提交

`prepareSocialReply` 复验窗口身份、可见内容快照、输入框状态和发送按钮绑定，返回只在本机有效的**30 秒单次 ticket**。准备阶段不写入、不触发发送。前端在提交前再次检查本次草稿、白名单、暂停、语言、等待时间与风险规则。

`commitSocialReply` 在任何异步操作前消耗 ticket，再次验证相同目标与空输入框，要求原窗口在后台且输入框没有键盘焦点，再使用 `ValuePattern.SetValue` 直接赋值 Unicode，检查内容后调用所选按钮的 `InvokePattern`。直接赋值可绕过中英文输入法组合，但不是自动切换输入法，也不保证所有客户端支持；当前输入法组合状态可能无法确认。

实现不使用全局 `SendKeys`、模拟回车、剪贴板或猜坐标作为失败后的替代发送方式。无法得到唯一可靠控件时拒绝操作，交由本人在原客户端处理。

原生调用、超时或异常可能发生在部分操作之后。调用发送后的返回只记为 `unknown`，不能用一次 Invoke 调用证明平台接受消息。程序发现已有草稿就拒绝操作；UIA 复核与写入不是原子操作，两者之间的用户／控件变化仍可能发生。执行任务期间不要在目标客户端打字或切换会话。部分写入后不清空或恢复草稿，未知发送不重试；核对前不要重新创建任务发送相同文本。

| Linux 真实模型图片／语音报告 | 对具体公开样例的模型处理结果 | 任意聊天截图准确识别，或自动取得真实客户端媒体 |

新报告位于验证包的 `artifacts/validation/windows-features-local-linux.json`；检查 `failure`、各阶段结果和质量检查，不能仅看文件存在或进程退出。9B 对公开合成截图正确转录了“周六14:30在北门见，带蓝色雨伞。”并识别左红右蓝，首次浏览器缺失的失败记录保留在 `previousFailure`。这不是 Windows 客户端实测。

Windows 设备仍需验证：官方客户端版本、UIA 树与唯一控件、已有草稿、窗口切换、中文／英文输入法状态、不同 DPI、截图保护、暂停／超时，以及本人核对的一次发送过程。只有实测记录支持的客户端版本才能写为已通过。
