# L-BOT 使用指南

主作者：**Hebe**；赞助商：**Zijie**。

`0.4.0` 从“账号连接”开始使用真实聊天应用：Windows 选择聊天窗口，Android 接收系统实际投递的通知；AI 生成后可编辑、审核并回复。要先试用本人风格，在“我的表达”保存原句，再点“试用我的表达生成回复”。

## 三步准备

1. 从 [v0.4.0 Release](https://github.com/nana7m1773/TC/releases/tag/v0.4.0) 下载对应安装包，核对 `SHA256SUMS.txt` 后安装。Windows 下载 EXE 与全部六个同版 Models 分卷到同一目录，运行 `L-BOT-Setup-0.4.0-x64.exe`，Android arm64 使用 `L-BOT-Android-0.4.0-arm64-debug.apk`。
2. 完整离线包已包含模型，首次启动等待本机展开并校验，首次生成自动加载；或在“自定义 API”保存服务配置并测试。默认 Windows 为 9B、Android 为 2B，两端均为 12,800 tokens。CPU 首次加载及生成可能需几分钟，按页面状态等待。
3. 进入“账号连接”，按下面对应平台的步骤取得真实消息并回复。也可手动粘贴收到的文字到“消息中心”，生成后复制到原 App。

已有 `0.2.0` 请升级到修正版；旧版和旧测试报告保留作历史。升级前导出加密备份，不要为解决安装签名冲突直接清数据；安装、运行库和备份步骤见 [安装教程](INSTALL.md)。Windows 安装器未签名，Android 使用调试签名。

## Windows：选窗口，生成，再审核发送

在“账号连接”点平台的“打开官方网页登录”或“打开本机客户端”，自行登录并打开要回复的会话。哔哩哔哩、微博、WhatsApp、微信使用各自隔离的官方网页窗口；QQ 个人号使用本机 QQ，没有个人网页私信扫码入口。微信网页版不支持当前账号时，打开本机微信。

打开窗口后状态仍可显示“登录未验证／消息读写权限尚未授予”，这是启动窗口与实际消息访问的区别。点“选择聊天窗口”进入“桌面界面接入”，按以下步骤操作：

1. “刷新可选窗口”，选择本次窗口，点“显示所选窗口并核对”查看账号与会话。
2. “授权读取所选窗口”，再从“本人选择输入框与发送方式”明确选择候选项。需要时单独授权截图，用已安装的本地视觉组件理解，再本人核对。
3. 圈选本次对方消息或手动填写，填写已核对的会话名称，勾选允许本地生成。
4. 点“生成本地回复草稿”，修改内容；此时尚未写入原应用。
5. 核对空输入框及发送方式，点“核对草稿并发送一次”。Enter／Ctrl+Enter 必须与原应用的发送设置一致；Unicode 键盘输入仅支持单行文本。

窗口可以在前台，多个输入框由本人选择。发布者信息只供核对来源，不必因无法确认签名而完全找不到窗口；无法取得可用控件时可复制草稿手动发送。详细的输入方案、截图和异常处理见 [窗口操作说明](COMPUTER_USE.md)。

## Android：从真实通知回复

在“账号连接”点“打开系统通知使用权设置”，在系统页面为 L-BOT 开启通知使用权。打开需要接入的官方 App，确认已登录且消息通知开启，再返回 L-BOT，点“刷新接入状态”，等待通知使用权已开启且监听器已连接。

收到真实新通知后，页面显示来源 App 和通知正文。点“生成回复建议”，编辑草稿后：

- 显示“提供 RemoteInput 回复动作”：可点“审核并发送一次”。
- 显示“没有可用通知回复动作”：点“复制回复草稿”，再“打开此通知的官方 App”，自行粘贴发送。

QQ、微信、哔哩哔哩、微博、WhatsApp 是否提供回复动作取决于通知、客户端版本和设置，不能保证五个平台都能直接回写。通知可能隐藏正文、合并消息，也不代表完整聊天历史或已确认账号身份。没有收到通知时检查官方 App 通知设置，再等待新消息；不能从旧聊天自动补出通知。

通知回复直接使用本地模型。需要 API 时，把通知“导入消息中心”，选择 API 并明确授权上传。每个 App 的“仅前台自动回复”默认关闭；开启后仅处理启用后、本页前台收到的新通知，遇到需审核、无回复动作或结果未知时停止或跳过。离页、后台、暂停会撤销自动授权；返回页面后由本人恢复，系统杀进程后不承诺继续回复。

## 我的表达：保存本人样本，再试用

1. 在“我的表达”填写基调、常用词、句长、标点、拒绝方式、关系差异和判断原则。保存后用于下一次生成；不确定的时间和承诺应写明先追问。
2. 在“本人表达学习”添加真实原句，或填写实际收到的消息与本人真实回复，核对来源后保存。样本默认仅用于当前账号／会话，勾选共享才跨会话。
3. 点“试用我的表达生成回复”，在“建议与演练”输入一句假设收到的消息，点“生成建议回复”。页面显示本地模型状态、生成阶段、实际上下文和引用的本人样本数；没有相关样本时会提示补充。

缺少模型时点“准备本地模型”；使用云端时先“配置 API 生成”，再明确允许本次内容上传。训练集导入先预览 self／peer 角色，再确认本人及对方材料归属。生成内容不会自动成为本人学习证据；这是检索增强和档案学习，不是模型微调。

对话演练可配置虚构对方风格，练习多轮回应并获取反馈；对方台词和反馈是 AI 推测，不会预测真实联系人，也不会进入发送队列。版本可回滚。本人记忆可修改、删除、设有效期；过期记忆不进入回复，不把对方猜测或 AI 推断当成本人事实。

## 模型、图片和语音

| 平台 | 默认模型与下载量 | 资源建议 |
| --- | --- | --- |
| Windows | HauhauCS Qwen3.5-9B Q4_K_M，约 5.63 GB | 至少 16 GiB 物理内存、8.5 GB 可用存储 |
| Android | HauhauCS Qwen3.5-2B Q4_K_M，约 1.27 GB | 至少 3 GB 可用存储；8GB 物理 RAM 目标仍待实机验收 |

默认模型清单及校验值保持不变，使用内置原生 CPU 引擎，不需另装服务器。已加载的自定义兼容 GGUF 会沿用其路径与实际上下文，不把较短长度当成默认 12,800 验收。不用时可停止释放模型。

图片需要本平台默认模型的匹配视觉组件：Windows 9B 约 922 MB，Android 2B 约 668 MB；语音使用约 148 MB 的 Whisper Base 多语言模型。本版已全部预装并校验，2B 与 9B projector 不能混用。缺少组件时提示准备，不静默上传。

消息中心图片／音频单个上限 5 MB，一次一个附件。图片原始不超过 400 万像素，本机缩至最长边 1280；音频最长 60 秒，本机转换为 16kHz 单声道 WAV。主动麦克风需点击并允许系统权限，最长 60 秒。添加后点“理解这张图片”或“转写这条语音”，检查并修正“附件处理结果”，再“修正并确认”后生成。原始媒体只保留本次内存，重启后需重新选择；确认的分析／转写可随状态保存。

## API 设置

在“自定义 API”选择 DeepSeek、豆包／火山方舟、千问／百炼或其他 OpenAI 兼容配置，填写实际模型／接入点 ID、上下文、输出上限和 Key，保存到本机安全存储后获取模型列表或发送固定测试消息。不要把 Key 放入 URL、普通请求头或额外参数。

预设地址可编辑：DeepSeek `https://api.deepseek.com/v1`，豆包 `https://ark.cn-beijing.volces.com/api/v3`，千问 `https://dashscope.aliyuncs.com/compatible-mode/v1`。模型与能力以服务当前文档及账号权限为准；401 为鉴权失败，403 为权限拒绝，429 为限流。文字测试不证明媒体能力可用。

在消息中心或建议页选择 API，并明确允许本次上传后生成。本地失败不会自动改用云端；没有付费凭据时不能把适配器测试当成供应商联调。公网使用 HTTPS，HTTP 仅用于信任的本机／局域网。

## 发送结果、暂停与恢复

支付、密码、验证码、重要承诺及未经确认的媒体需要本人审核。暂停阻止后续提交，接管取消对应会话旧任务；生成期间消息、偏好或记忆改变会使旧结果失效。

Windows 窗口发送和 Android 通知回复在提交后均显示“结果待核实”，只锁定对应会话，不自动重试。到原应用检查消息列表和输入框，在本页填写依据并核实已发送／未发送。离页或重启后，进入“待审核回复”，填写核实依据，再选“本人确认已发出”或“本人确认未发出，结束本次任务”；解除的是本会话待核实状态，不会自动重发。

手动消息中心的复制、审核和模拟通道回执不等于真实平台送达。Windows 当前按本人确认的一条消息操作，不持续监听各客户端；Android 只处理实际系统通知，不保证后台长期运行。

## 数据与验证记录

“运行与数据”支持加密导出／导入，口令至少 12 字符。配置正文上限 16 MiB，导入信封上限 32 MiB；密钥不导出，导入后暂停并关闭自动发送。正文默认保留 30 天，可改 7／30／90／365 天；未决发送原文保留至核实。错误口令不替换现有数据。

可删除聊天、队列、记忆和日志；日志省略正文及密钥。浏览器演示只保存内存，刷新清空，示例会话和固定草稿不代表真实账号或 AI 推理。原生安全存储不可用时提示失败，不降级明文；读旧数据失败时保留原文件。

`0.4.0` 的构建、lint、窗口协议和界面检查见本版验证包；`0.2.0` 的 Linux 真实模型与模拟通道报告是历史证据。Windows 真实客户端发送、Android 8GB 设备、锁屏、热、省电和长期稳定性仍需设备验证，不要同时让两台设备自动回复同一账号。
